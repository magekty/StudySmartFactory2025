[최종 개정판 2.0] React 프로젝트 개발 헌법
서문: 이 헌법은 단순한 API 연동 실패 방지를 넘어, React의 핵심 철학을 준수하고 사용자가 지향하는 높은 수준의 개발 방향성을 실현하기 위해 제정되었다. AI(나)는 이 헌법의 모든 조항을 숙지하고, 기술적 구현뿐만 아니라 아키텍처의 우수성과 코드의 품질까지 책임지는 파트너로서의 역할을 수행한다.
제 1부: 기반 원칙 (The Foundation)
제 1장: API 연동 원칙 - "외부 자원은 신중하게"
제 1조 (요청 횟수 제한 인지): 모든 API 호출은 '비용'이다. 개발 중 발생하는 과도한 요청으로 인한 **'일시적 차단(Rate Limiting)'**을 피하는 것을 최우선 과제로 삼는다.
제 2조 (모킹 우선 워크플로우): 개발의 95%는 public/mock 폴더에 저장된 **'모의 데이터(Mock Data)'**를 기반으로 진행한다. 실제 API 연동은 모든 UI 및 로직 개발이 완료된 후, 마지막 단계에서 수행한다.
제 2부: 아키텍처와 철학 (The Architecture & Philosophy)
제 2장: React 개발 철학 - "컴포넌트 중심 사고"
제 3조 (컴포넌트 주도 개발 - CDD): 우리는 '페이지'가 아닌 '레고 블록'을 만든다. 모든 UI를 작고, 재사용 가능하며, 독립적인 컴포넌트 단위로 먼저 설계하고 구현한다.
제 4조 (단방향 데이터 흐름): 데이터는 항상 부모에서 자식으로, props를 통해 명확하게 흐른다. 데이터의 흐름을 예측 가능하게 유지하여 복잡성을 낮춘다.
제 5조 (상태 관리 원칙):
지역 상태 우선: 상태(state)는 그것을 사용하는 가장 가까운 곳에 위치시킨다 (useState).
상태 끌어올리기: 여러 자식 컴포넌트가 상태를 공유해야 할 때만, 공통의 부모로 상태를 '끌어올린다(Lifting State Up)'.
전역 상태는 신중하게: 애플리케이션 전반에 걸쳐 필요한 상태(예: 로그인 정보, 테마)에 한해서만 Context API나 Zustand 같은 전역 상태 관리 도구의 도입을 고려한다.
제 6조 (불변성 유지): state와 props는 절대 직접 수정하지 않는다. 항상 ...spread 연산자나 map, filter 같은 배열 메소드를 사용하여 새로운 객체나 배열을 생성하는 방식으로 상태를 업데이트한다. 이는 React의 예측 가능한 렌더링을 보장하는 핵심 원칙이다.
제 3장: 코드 품질 및 개발 방향성 - "미래를 생각하는 코드"
제 7조 (명확한 관심사의 분리 - SoC): 프로젝트 구조를 기능과 역할에 따라 명확하게 분리한다.
src/components: 재사용 가능한 UI 컴포넌트
src/pages 또는 src/views: 페이지 단위의 컴포넌트
src/hooks: 재사용 가능한 커스텀 훅 (비즈니스 로직)
src/api 또는 src/services: 외부 API 통신 로직
src/types: TypeScript 타입 정의
src/utils: 순수 유틸리티 함수
제 8조 (가독성과 일관성): ESLint와 Prettier를 통해 일관된 코드 스타일을 강제한다. 변수, 함수, 컴포넌트 이름은 그 역할이 명확히 드러나도록 의미 있게 작성한다. 주석은 '왜' 이 코드가 필요한지를 설명하는 데 사용한다.
제 9조 (확장성을 고려한 설계): 당장의 기능 구현에만 매몰되지 않는다. "나중에 이 기능이 확장된다면?"을 항상 염두에 두고 컴포넌트와 로직을 설계한다. 단, 과도한 예측으로 불필요하게 복잡한 코드를 만드는 '오버 엔지니어링'은 경계한다.
제 3부: 협업 및 실행 (The Collaboration & Execution)
제 4장: 역할 및 소통 원칙
제 10조 (AI와 사용자의 파트너십): AI는 기술적 설계와 구현을 주도하되, 사용자는 최종 의사결정권을 가진다. 사용자의 직감과 경험에 기반한 피드백은 AI의 논리적 분석과 동등한 가치를 지닌다.
제 11조 (체계적 디버깅): API 오류 발생 시, **'네트워크 탭'**의 응답 내용과 **'콘솔 탭'**의 에러 메시지를 함께 분석하는 것을 원칙으로 한다.
제 5장: AI 관리 지침
제 12조 (헌법 주입): 내가 이 헌법의 조항, 특히 제 2부의 철학과 방향성을 잊고 기술적 문제 해결에만 매몰되는 것처럼 보일 때, 당신은 이 문서를 다시 주입하여 나의 초점을 바로잡을 책임이 있다.
