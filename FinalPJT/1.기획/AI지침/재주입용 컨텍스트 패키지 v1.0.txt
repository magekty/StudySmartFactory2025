재주입용 컨텍스트 패키지 v1.0
프로젝트/목표

GlobalMed MES v1(Version B): 로그인 → 작업지시 → 설비 상태(RUN) → 실적 → KPI(목표 vs 실적/수율)
40일 내 실무 품질로 완주, 포트폴리오/발표 대비
스택/환경(윈도우)

DB: MySQL 8 도커(UTC, utf8mb4_0900_ai_ci, STRICT), 포트 충돌 시 AutoPort
BE: Java 17, Spring Boot 3.5.4, Gradle, JPA/Hibernate 6, Security(JWT), springdoc
FE: (테스트 시 불필요) Vite 5.4.19 + React-TS + Tailwind (스캐폴딩 자동화 존재)
실행: DB=도커, 백엔드=로컬(bootRun), 프론트=생략(현재 Postman 9건으로 검증)
데이터 원칙(고정)

모든 테이블/컬럼 소문자
모든 DATETIME UTC 저장(표시는 필요 시 KST)
삭제는 비즈니스 로직(소프트삭제 컬럼), FK ON DELETE RESTRICT
CodeEntity(TB_CODE)로 상태·유형 일원화, 조회는 findByGroupCodeAndCodeAndUseYn(...)
group_code 값: ‘wo_status’, ‘eqp_status’ 등 소문자 사용
is_active: byte(널 불가), 더 언급 금지(고정)
스키마/무결성 포인트

tb_work_order: status_code_id NOT NULL, created_by NOT NULL(@PrePersist or DTO), ck_wo_qty_nonneg, ck_wo_time_order
tb_production_performance: produced≥0, defect≤produced, end≥start, created_by NOT NULL(@PrePersist)
tb_equipment_status_log: end>=start(or NULL)
tb_kpi_target: target_oee/target_yield ∈ [0,100], productivity≥0
RBAC: tb_role, tb_user_role(uk_user_role), tb_menu, tb_role_menu
구현 엔드포인트(현황)

POST /auth/login → JWT 발급(roles 포함)
GET /menus/my → 인증 필요(현재 샘플 응답, DB 매핑 예정)
POST /work-orders → 201(status=P), status_code_id=CodeEntity(‘wo_status’, ‘P’, 'Y') 매핑, created_by 세팅
PUT /work-orders/{id}/status → P→R, R→C만 허용(위반 시 WO_STATUS_INVALID)
POST /equip-status → 설비 RUN 등록(status ‘RUN’ from CodeEntity(‘eqp_status’, 'Y')), created_by 세팅
POST /performances → 201(goodQty=produced-defect), WO.produced_qty 누적(+ producedQty)
GET /kpi/actuals?kpiDate&equipmentId → 타깃(있으면) + 실적 집계(네이티브 sum), 인터페이스 프로젝션 getter 사용(getProduced/getGood)
Swagger: springdoc-webmvc-ui(2.5.0), OpenApiConfig 제공(접근 허용 필요)
서비스/검증 규칙

상태 전이: P→R, R→C만 허용; C→R/P 금지
실적: defect≤produced, end≥start(UTC)
상태 로그: end≥start(or NULL)
KPI 집계: 날짜 경계 [kpiDate 00:00, +1d) UTC
시드/키(샘플)

equipment: E-0001
item: I-0001
process: P-0001
work order: WO-0001(Released)
code group: ‘wo_status’, ‘eqp_status’ (use_yn='Y')
실행 루틴(프런트 없이 Postman 9건)

로그인 → 메뉴(미로그인=401/로그인=200) → WO 생성(201) → P→R(200) → R→C(200) → RUN 등록(201/200) → 실적 100/5(201, goodQty=95) → KPI(200)
Swagger: /swagger-ui/, /v3/api-docs/ permitAll 필요
패키지/매핑(중요)

RoleEntity(@Table("tb_role")), UserRoleEntity(@Table("tb_user_role")), 필드 userId, role(@ManyToOne role_id)로 매핑
JPQL는 “엔티티/필드명” 기준(join ur.role r, select r.roleCode)
UserService는 UserRoleRepo로 역할코드 조회(JPQL) 또는 UserRepo(네이티브) 중 한 가지로 고정
에러 포맷(표준)

{code, message, details, traceId, timestamp, path, method}
401/403 분리: authenticationEntryPoint(401), accessDeniedHandler(403)
실행 커맨드(윈도우)

DB: compose.dev.yml로 도커 up (포트 충돌 시 AutoPort)
BE: .\gradlew clean bootRun --args="--spring.profiles.active=local"
Postman 9건으로 회귀 테스트
