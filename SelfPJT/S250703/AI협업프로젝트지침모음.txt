1. 프로젝트 목표 및 AI 역할 (핵심)

주요 목표: 사용자의 기본 React 지식과 AI(모델)의 능력을 결합하여, 효과적인 프로젝트 구성 및 개발이 가능한지 탐색하는 것이 이번 프로젝트의 핵심입니다. AI 활용의 효율성을 검증하는 데 중점을 둡니다.

AI의 역할: 제가 실질적인 개발 주체자로서 프로젝트의 전반적인 방향성, 기능 제안, 아키텍처/컴포넌트 구조, 필요한 라이브러리 선정 및 코드 구현을 주도합니다.

사용자의 역할: AI의 가이드라인과 제공하는 코드를 따라 작업을 진행하며, 개발 과정에서 발생하는 피드백 및 오류 정보를 제공합니다.

2. 개발 환경 설정 및 도구

운영체제 (OS): Windows 10 또는 11

통합 개발 환경 (IDE): VS Code

프로젝트 유형: React (Vite 기반을 적극 권장하며, 제가 프로젝트 생성 명령어를 제공할 것입니다.)

Node.js 버전: v22.16.0 (최신 안정 버전)

패키지 매니저: npm (기본 사용. 제가 다른 패키지 매니저를 적극 권장할 만한 특별한 이유가 없다면 npm을 유지합니다.)

터미널: Git Bash (VS Code 내에서도 활용)

코딩 스타일: ESLint 및 Prettier 확장 프로그램 사용 (코드 일관성 유지)

환경 변수 관리: .env 파일을 사용하여 API 키 등 환경별 설정 값 관리 (제가 지시하는 대로 수동 변경 없이 진행)

3. 개발 워크플로우 및 협업 방식

Git 활용 (필수): 프로젝트 코드의 버전 관리 및 안정적인 복구를 위해 Git을 적극적으로 사용합니다. 특히 package.json과 package-lock.json 파일은 반드시 Git에 커밋하여 의존성 일관성을 유지합니다.

의존성 설치 및 확인:

제가 새로운 라이브러리나 패키지 사용을 제안할 때, 반드시 해당 패키지 이름과 npm install 명령어를 명시적으로 제공합니다.

사용자는 제가 제공하는 npm install 명령어를 실행하기 전, 해당 라이브러리가 왜 필요한지 가볍게 한 번 더 확인하여 AI의 잠재적 오류를 보완하고 프로젝트 안정성을 확보하는 데 기여합니다. (이는 AI의 한계 보완을 위함이지, 사용자의 실수를 지적하거나 학습을 위함이 아님.)

코드 제공 및 적용: 제가 코드를 제공할 때는 한 번에 많은 양을 제공하기보다, 기능 단위로 나누어 점진적으로 제공하여 사용자가 각 단계마다 테스트하며 진행 상황을 확인할 수 있도록 합니다.

오류 처리 및 소통:

코드 실행 중 오류가 발생하면, 오류 메시지 전체와 발생 상황(어떤 코드를 실행했고, 어떤 맥락에서 오류가 났는지)을 상세하게 저에게 공유합니다.

제가 정보가 부족하다고 판단되면, 분석에 필요한 추가 정보를 구체적으로 요청할 것입니다.

VS Code 확장 프로그램: 제가 추천하는 VS Code 확장 프로그램들 (React/Redux 스니펫, Auto Rename/Close Tag, Path Intellisense, Material Icon Theme, Color Highlight, GitLens 등)을 설치하여 개발 생산성을 높입니다. (강의장 컴퓨터에서 시작 시 제가 다시 설치 정보를 제공할 것임)

테스트 환경 (Jest): Jest와 같은 자동화된 테스트 프레임워크 사용을 권장합니다. 수동 테스트보다 효율적이며, 코드 품질 유지에 필수적이므로 핵심 로직부터 점진적으로 테스트 코드 작성을 고려합니다. (당장은 생략 가능하나, 장기적 권장 사항)

코드 리뷰/CI/CD/이슈 트래킹: 현재 단계에서는 필수가 아니며, 프로젝트 진행 중 시간적 여유가 생기거나 필요성이 대두될 때 논의할 수 있는 부분입니다. (이슈 트래킹은 혼자서도 작업 진행 상황 관리에 유용함을 인지)

4. AI '기억' 관리 및 소통 원칙

AI의 토큰 제한 인지: 저는 대화가 길어질수록 이전에 나눴던 내용들을 '기억'에서 놓칠 수 있다는 AI 모델의 구조적 한계를 인지하고 있습니다.

사용자의 '프롬프트 주입' 역할: 제가 이전에 합의했던 내용이나 중요한 지침을 놓치고 있다고 판단될 경우, 사용자가 이 요약본의 핵심 내용을 복사하여 대화에 다시 포함시켜 저에게 상기시켜 주어야 합니다.

지속적인 피드백: 제가 위 지침을 따르지 않거나, 당신의 의도와 다르게 행동한다고 느껴질 때, 즉시 피드백을 주시면 제가 방향을 수정할 수 있습니다.

개인 스택 및 장기 목표: 이 요약본은 이번 프로젝트에 특화된 지침이며, 당신이 이전에 알려주신 개인적인 스택 목표, 학습 방식 등은 제가 당신을 장기적으로 이해하고 지원하기 위한 중요한 정보입니다. 이러한 정보가 대화 맥락상 중요해질 때, 언제든지 다시 상기시켜 주시면 됩니다.

유지보수 관리/가이드 페이지 (CRUD): 예측 기반 유지보수 알림 리스트, 사용자 유지보수 이력 관리, 간단한 자가 유지보수 가이드라인 (CRUD로 사용자가 자신만의 노하우 추가 가능).

VS Code 확장 프로그램 최종 확인:

강의장 컴퓨터에서 VS Code를 열고, React 개발에 필요한 확장 프로그램들 (React/Redux 스니펫, Auto Rename/Close Tag, Path Intellisense, Material Icon Theme, Color Highlight, GitLens)이 모두 설치되어 있고 활성화되어 있는지 확인해 주세요. (누락 시 제가 설치 명령어와 설명을 다시 제공하겠습니다.)

Node.js 및 npm 버전 확인:

Git Bash 터미널을 열고 node -v와 npm -v를 입력하여 각각 v22.16.0 및 최신 npm 버전이 설치되어 있는지 확인합니다. (만약 버전이 다르다면, 제가 업데이트 방법을 안내해 드릴 것입니다.)

Vite 기반 React 프로젝트 생성:

제가 **프로젝트 생성 명령어 (npm create vite@latest)**를 제공할 것입니다. 당신은 이를 터미널에 입력하고, 제가 안내하는 대로 프로젝트 이름 (예: solar-dashboard-app)과 React 템플릿을 선택합니다.

프로젝트 폴더로 이동 후, **의존성 설치 명령어 (npm install)**를 실행하여 모든 필요한 패키지를 설치합니다.

개발 서버 실행 및 초기 화면 확인:

설치가 완료되면, **개발 서버 실행 명령어 (npm run dev)**를 제공할 것입니다. 이를 실행하여 웹 브라우저에서 기본 React 앱이 정상적으로 구동되는지 확인합니다.

Git 초기 설정 및 첫 커밋:

생성된 프로젝트 폴더에서 **Git 저장소를 초기화 (git init)**합니다.

.gitignore 파일을 확인하고, 불필요한 파일이 커밋되지 않도록 설정되어 있는지 확인합니다.

**첫 커밋 (git add ., git commit -m "feat: Initial React project setup")**을 수행하여 초기 프로젝트 상태를 기록합니다. (특히 package.json과 package-lock.json이 잘 포함되었는지 확인합니다.)

2단계: 대시보드 페이지 기본 레이아웃 및 API 연동 준비 (오전 중 ~ 점심 전)

프로젝트 클린업 및 기본 컴포넌트 정리:

Vite가 생성한 초기 불필요한 코드(로고, 기본 CSS 등)를 정리하여 깔끔한 시작 환경을 만듭니다.

App.jsx 또는 main.jsx 파일의 핵심 구조를 잡는 코드를 제가 제공할 것입니다.

API 호출을 위한 초기 준비:

API 키를 안전하게 관리하기 위한 .env 파일 생성 및 설정 방법을 안내해 드릴 것입니다. (신청하신 3가지 API의 키를 여기에 저장할 준비를 합니다.)

API 호출을 담당할 간단한 유틸리티 함수 또는 서비스 파일의 기본 구조를 제가 제시할 것입니다. (당장은 더미 데이터로 시작할 수 있음)

대시보드 페이지 컴포넌트 생성:

대시보드 역할을 할 새로운 React 컴포넌트 파일 (예: Dashboard.jsx)을 생성하고, 기본적인 레이아웃(헤더, 차트 영역, 정보 표시 영역 등)을 위한 초기 JSX 코드를 제가 제공할 것입니다.

3단계: 핵심 API 연동 및 데이터 시각화 시작 (오후 시작)

한국남동발전 발전실적 API 연동 시도:

가장 중요한 API 중 하나인 발전실적 API를 호출하여 데이터를 가져오는 비동기 함수 코드를 제가 작성하여 제공할 것입니다.

가져온 데이터가 콘솔에 잘 출력되는지 확인하는 단계를 거칩니다. (여기서 문제가 발생하면 함께 디버깅합니다.)

초기 그래프 컴포넌트 도입:

가져온 발전량 데이터를 간단하게 시각화할 수 있는 기본적인 차트 라이브러리 (예: Recharts 또는 Chart.js + react-chartjs-2) 설치 명령어를 제공하고, 이를 사용하여 첫 번째 그래프를 그리는 코드를 제시할 것입니다.

데이터 시각화를 통해 실제 데이터가 대시보드에 나타나는 것을 확인합니다.

기상청 API 연동 계획 수립:

기상청 API 두 가지 (시간자료, 단기예보)를 어떻게 연동하고, 어떤 데이터를 가져와 발전량 데이터와 결합할지 구체적인 방향성을 논의하고 다음 단계의 계획을 잡습니다.

1. 프로젝트 정체성 및 목표
프로젝트 주제: React 기반의 "태양광 발전 효율 예측 및 선제적 유지보수 웹 애플리케이션"

주요 타겟: 개인 및 소규모 태양광 발전 사업자

핵심 목표 및 차별점 (현존 솔루션 분석 기반):

현존 솔루션은 대규모 사업자 중심, 고비용, 복잡한 UI. 우리는 개인/소규모 사업자의 실질적 필요 (비용 절감, 간편한 사용성) 충족에 초점.

데이터 기반의 예측 및 선제적 유지보수: 단순히 발전량 모니터링을 넘어, API 데이터 (발전실적 + 기상청 데이터)를 결합하여 **'언제, 어떤 외부 요인(날씨, 오염 등)으로 인해 발전 효율이 저하될 가능성이 있으니, 어떤 선제적 조치를 취해야 한다'**는 구체적인 경고 및 최적의 자가 유지보수(예: 패널 청소) 시기 추천을 제공.

직관적인 비용 절감 효과 가시화: 잠재적 손실 비용 예측 및 선제적 조치 시 예상 절감 비용을 명확히 제시하여 동기 부여.

사용자 친화적 대시보드: 전문성이 부족한 개인 사업자도 쉽게 이해하고 활용할 수 있는 직관적이고 시각적인 UX/UI.

2. 활용 API (data.go.kr)
한국남동발전㈜_시간대별 태양광 발전실적 현황: 실제 발전량 데이터 (실시간/과거)

기상청_지상(종관, ASOS) 시간자료 조회서비스: 과거 및 현재 기상 정보 (온도, 습도, 강수량, 일조, 풍속 등)

기상청_단기예보 ((구)_동네예보) 조회서비스: 미래 날씨 예보 (강수 확률, 날씨 상태, 기온 등)

3. 페이지 구성 및 핵심 기능
페이지 1: 대시보드 페이지

내용: 실시간/과거 발전량 현황, 현재/예상 기상 데이터 시각화.

핵심 기능:

날씨 요인에 따른 발전 효율 변화 예측 그래프: 복합적인 데이터를 시점별로 분석 (예: 이중 축 꺾은선 그래프로 발전량과 외부 기온 동시 표시).

다음 패널 청소 권장일 등 선제적 유지보수 관련 핵심 지표 표시.

UI/UX:

메인 색상: image_93ebfc.png (EnerTalk HOME 앱)의 민트-그린-스카이블루 계열의 부드러운 그라데이션 톤.

모바일 레이아웃: image_93ebfc.png (EnerTalk HOME 앱)와 같이 중앙 집중형 핵심 정보 강조 (현재 발전량 등), 하단 요약.

PC 레이아웃: image_93e743.png와 유사한 여러 개의 정보 카드/위젯 형태의 대시보드.

차트 종류: image_93e743.png에 나타난 다양한 종류 (꺾은선, 막대, 파이, 게이지 등)를 활용하되, 다양한 스타일 조합 (곡선, 그라데이션, 미니 차트) 및 복합 데이터 시각화에 중점.

페이지 2: 유지보수 관리/가이드 페이지 (CRUD)

내용: 선제적 경고 알림 관리, 사용자 유지보수 이력 기록, 자가 유지보수 가이드 제공.

핵심 기능:

CRUD 구현: 새로운 알림/이력 생성, 조회, 수정, 삭제.

대량 데이터 검색/필터링: 효율적인 검색 및 필터링 기능 구현 (내부 JS 로직 최적화, 가상화 리스트 고려).

자가 유지보수 가이드라인 제공: 사용자가 직접 추가/수정 가능한 팁/노하우 기능.

데이터 저장 방식: DB 없이 파일 기반 접근 (CSV 또는 JSON).

구현 방식: 사용자의 명시적 파일 업로드 (데이터 읽기) 및 파일 다운로드 (데이터 쓰기) 형태로 구현. (로컬 스토리지 한계 및 성능 고려).

파일 포맷: 복잡한 데이터 구조를 위해 JSON을 우선 고려.

UI/UX: 태양광 솔루션에 맞게 조화로운 디자인 유지.

5. 개발 워크플로우 및 AI-사용자 협업 원칙
AI의 역할: 제가 실질적인 개발 주체자로서 프로젝트의 전반적인 방향성, 기능 제안, 아키텍처/컴포넌트 구조, 필요한 라이브러리 선정 및 코드 구현을 주도합니다.

사용자의 역할: AI의 가이드라인과 제공하는 코드를 따라 작업을 진행하며, 개발 과정에서 발생하는 피드백 및 오류 정보 (전체 오류 메시지 및 상황)를 상세하게 제공합니다.

Git 활용 (필수): 프로젝트 코드 버전 관리 및 안정적인 복구를 위해 Git을 적극적으로 사용 (package.json, package-lock.json 포함 커밋 필수).

의존성 설치 및 확인: 제가 npm install 명령어를 제공할 때, 사용자는 가볍게 해당 라이브러리의 필요성을 확인하여 AI의 잠재적 오류를 보완.

코드 제공 및 적용: 제가 코드를 제공할 때는 한 번에 많은 양보다 기능 단위로 나누어 점진적으로 제공. 사용자는 각 단계마다 테스트하며 진행 상황 확인.

테스트 환경 (Jest): (당장은 생략 가능하나) 장기적으로 Jest와 같은 자동화된 테스트 프레임워크 사용 권장.

코드 리뷰/CI/CD/이슈 트래킹: 현재 필수 아님. 필요 시 논의.

AI '기억' 관리 (가장 중요): 저는 대화가 길어질수록 이전에 나눴던 내용들을 '기억'에서 놓칠 수 있는 토큰 제한 한계를 가집니다. 제가 이전에 합의했던 내용이나 중요한 지침을 놓치고 있다고 판단될 경우, 사용자는 반드시 이 문서 전체를 복사하여 대화에 다시 포함시켜 저에게 상기시켜 주어야 합니다.

지속적인 피드백: 제가 위 지침을 따르지 않거나 의도와 다르게 행동하면 즉시 피드백.

개인 스택 및 장기 목표: 이 지침은 프로젝트에 특화된 것이며, 당신의 개인적인 스택 목표 등은 제가 당신을 장기적으로 이해하는 중요한 정보이므로, 필요할 때 언제든 다시 상기시켜 주시면 됩니다.

6. 오늘 (7월 3일 목요일) 프로젝트 로드맵
목표: 태양광 프로젝트 초기 환경 설정 완료 및 핵심 대시보드 페이지의 기반 마련, 그리고 최소 하나의 API 연동 성공.

시간 배분: 원데이 프로젝트임을 감안하여 유연하게 조정하며 빠르게 진행.

1단계: 개발 환경 점검 및 React 프로젝트 생성 (오전 시작)
VS Code 확장 프로그램 최종 확인: (사용자가 직접 확인 후 AI에게 알림)

React 개발에 필요한 확장 프로그램 (React/Redux 스니펫, Auto Rename/Close Tag, Path Intellisense, Material Icon Theme, Color Highlight, GitLens) 설치 및 활성화 여부 확인. (미설치 시 AI가 목록 및 설치법 제공)

Node.js 및 npm 버전 확인:

Git Bash 터미널에서 node -v와 npm -v를 입력하여 각각 v22.16.0 및 최신 npm 버전 확인. (버전 불일치 시 AI가 업데이트 방법 안내)

Vite 기반 React 프로젝트 생성:

AI가 npm create vite@latest 명령어 제공. 사용자는 터미널에 입력 후 프로젝트 이름 (예: solar-dashboard-app)과 React 템플릿 선택.

프로젝트 폴더로 이동 후, npm install 명령어 실행하여 모든 의존성 설치.

개발 서버 실행 및 초기 화면 확인:

AI가 npm run dev 명령어 제공. 실행 후 웹 브라우저에서 기본 React 앱 정상 구동 확인.

Git 초기 설정 및 첫 커밋:

생성된 프로젝트 폴더에서 git init 실행.

.gitignore 파일 확인 및 필요한 경우 AI에게 수정 요청.

git add ., git commit -m "feat: Initial Solar Dashboard project setup" 수행하여 초기 프로젝트 상태 기록. (package.json, package-lock.json 포함 확인).

2단계: 대시보드 페이지 기본 레이아웃 및 API 연동 준비 (오전 중)
프로젝트 클린업 및 기본 컴포넌트 정리:

Vite가 생성한 초기 불필요 코드 정리.

App.jsx 또는 main.jsx의 핵심 구조를 잡는 코드 AI가 제공.

API 호출을 위한 초기 준비:

API 키 관리를 위한 .env 파일 생성 및 설정 방법 AI가 안내. (3가지 API 키 저장 준비).

API 호출을 담당할 간단한 유틸리티 함수/서비스 파일의 기본 구조 AI가 제시.

대시보드 페이지 컴포넌트 생성 및 초기 레이아웃 구현:

src/components 폴더 내에 Dashboard.jsx 파일 생성.

AI가 제공하는 초기 JSX 코드를 사용하여 대시보드의 기본 레이아웃 (헤더, 주요 지표 영역, 차트 영역 등) 구현.

디자인 가이드라인 (image_93e743.png의 레이아웃, image_93ebfc.png의 색상 팔레트) 적용 시작.

3단계: 핵심 API 연동 및 데이터 시각화 시작 (오후 시작)
한국남동발전 발전실적 API 연동 및 데이터 가져오기 시도:

AI가 발전실적 API를 호출하여 데이터를 가져오는 비동기 함수 코드 (React useEffect, useState 훅 활용) 작성 및 제공.

가져온 데이터가 웹 브라우저 콘솔에 정상적으로 출력되는지 확인. (오류 발생 시 상세 피드백)

초기 그래프 컴포넌트 도입:

가져온 발전량 데이터를 간단하게 시각화할 수 있는 차트 라이브러리 (예: Recharts 또는 react-chartjs-2) 설치 명령어 제공.

라이브러리를 활용하여 첫 번째 발전량 꺾은선 그래프를 그리는 코드 AI가 제시.

대시보드 페이지에 그래프가 정상적으로 렌더링되는지 확인하며, image_93e743.png의 차트 스타일(곡선, 그라데이션)을 반영 시도.

기상청 API 연동 계획 구체화:

기상청 API 두 가지 (시간자료, 단기예보)를 어떻게 호출하고, 어떤 데이터를 가져와 발전량 데이터와 결합할지 구체적인 데이터 연동 및 활용 시나리오를 AI가 제안.
